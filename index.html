Sealgraf

Spend authorization for AI agents

The problem: AI agents can spend money, but nothing checks the owner's limits before the spend — or proves afterwards what was approved, by whom, and why.

Sealgraf is the authorization layer: the agent checks owner-set limits before spending, obtains the owner's approval on a surface the agent cannot fake, and seals a verifiable receipt for every transaction.

I designed and built the authorization layer and the integration packages for six agent frameworks — Dify, CrewAI, LangChain, n8n, Composio, and the Vercel AI SDK — each live-tested end-to-end with server-verified approval loops.

Case studies

Problem, my role, the hardest decision, and the result — for each featured project.

Sealgraf — case study

Problem — AI agents can spend money, but nothing checks the owner's limits before the spend, or proves afterwards what was approved, by whom, and why.

My role — I designed and built the authorization layer and the integration packages for six agent frameworks.

Hardest decision — Approval has to happen on a surface the agent cannot fake: the owner approves out-of-band, and the agent only ever learns the outcome.

Result — Live in production at sealgraf.com. All six integrations (Dify, CrewAI, LangChain, n8n, Composio, Vercel AI SDK) live-tested end-to-end with server-verified approval loops; technical paper published.

Doorway — case study

Problem — EAP utilization runs 3–8% because the access funnel leaks before care: undiscoverable benefits, eligibility traps, black-box matching, silent session caps.

My role — I built the complete journey: eligibility verification, benefit explanations with citations, steerable matching, approval-gated booking, and session balances derived from a sealed ledger.

Hardest decision — No clinical work, ever: crisis signals route to humans (988) before anything else, and eligibility, cost, and safety stay as rules in code. Employers see aggregates only, behind a cohort floor of 25 — a per-member employer view does not exist.

Result — Live demo running the full journey end-to-end; 44/44 tests, including a person-path walk and the privacy wall (the per-member employer route returns 404).

Reify — case study

Problem — Agent memory systems hand the model top-k clues and make it re-synthesize on every query — and none can answer "what changed?", because changes are not stored as data.

My role — I built a local-first memory engine: a bitemporal graph where transitions are first-class data, hybrid retrieval, and MCP / REST / CLI surfaces.

Hardest decision — Make the memory layer itself the reasoner — reconsolidation on write and materialized inferences — instead of retrieval-time-only synthesis; and forget-by-default TTLs, so memory can explain and expire itself.

Result — Open source, 442 tests. Its wedge demo — recalling that a title changed, across sessions — runs end-to-end with no LLM key.

ListProof — case study

Problem — Rental search works; everything after fails — wrong data with no correction path, scraped scam listings, screening errors, and fees nobody itemizes.

My role — I built the verification pipeline (ownership cross-checks, photo provenance, price-vs-market), the fee ledger with its hard budget gate, and correction tracking.

Hardest decision — Verdict discipline: the product never prints "safe." A records mismatch is "unresolved authority," not fraud — and a correction counts as fixed only when a fresh check independently re-verifies it.

Result — Working prototype, 58/58 tests; in the test corpus, no labeled scam listing ever reaches VERIFIED.
